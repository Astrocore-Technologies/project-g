# ADR 0013: Локальная мастерская баланса

## Status

Направление принято пользователем 2026-10-10: «делай» после уточнения локального инструмента разработчика. Административные права, региональные ограничения, подготовленные GM-операции и журнал сотрудников отложены. Данный ADR уточняет историческое [расширенное предложение](balance-tools-proposal.md).

## Context

На этапе разработки требуется менять существующие характеристики, оружие, навыки, пассивки и существ, сравнивать результат и быстро пробовать бой выбранным билдом. Баланс остаётся в серверном JSON; формулы уже есть в Server. Полный перенос всех контентных типов и production-инструменты управления увеличивают объём без необходимости для этого сценария.

## Decision

- `tools/BalanceStudio` — отдельный Godot .NET tools-проект с editable Main.tscn. Он не входит в игровой проект/экспорт.
- `tools/Balance.Core` — модель черновика, сравнение и управление тестовыми процессами. На этом этапе ссылается на существующую .NET-сборку `Content.Server`; entrypoint сервера от ссылки не исполняется. Ни Core, ни Server не ссылаются на Godot.
- Используются настоящий `ContentCatalog`, `StatCalculator` и общая `CombatBalanceMath`. Выделять всю server-only Rules-библиотеку пока не требуется. Игровой клиент продолжает ссылаться только на Shared; серверный каталог в него не включается.
- Источник — `Content.Server/Data/prototype.json`. Разделение на множество файлов отложено: нет второго авторского источника и нового manifest/release pipeline.
- Числа редактируются формами. IDs/ссылки, сценовые позиции и создание новых механик не подменяются числовыми полями. Проверку перед сохранением выполняет серверный загрузчик.
- JSON-дерево сохраняет нетронутые значения/разделы, включая коэффициенты 1/30 и 1/36. Проценты показываются с одним знаком, числовой ввод поддерживает запятую и точку. Поле без изменения текста не переписывается округлённым значением.
- Undo/redo хранит последние 64 состояния. Атомарная замена файла и проверка исходного hash предотвращают тихую перезапись внешней правки. Невалидный черновик можно сохранить отдельной копией, но нельзя применить/записать в исходник.
- Preview сравнивает текущий черновик с файлом при открытии/последнем сохранении. DPS — ожидаемая автоатака по неподвижной цели, без временных эффектов/ротации. Выбранный melee-приём отдельно показывает прямой урон выбранного уровня по полной цели.

### Индивидуальные уровни навыков — 2026-10-10

Пользователь одобрил расширение профессия → навыки → параметры и таблицы уровней. `AbilityDefinition.Progression` задаёт практику за успешное применение и массив строк (практика до следующего уровня, множитель силы). Максимум определяется длиной массива. Отсутствующая таблица наследует прежнюю общую формулу. Catalog schema 4 читает также legacy schema 3 без индивидуальных таблиц; существующие числовые результаты сохранены. Все навыки текущих профессий имеют явные таблицы.

`ContentCatalog` валидирует и индексирует эффективные кривые один раз при загрузке. Combat, выдача практики, загрузка сохранения, owner-only ProgressionState и tools используют одну кривую. Wire protocol и persistence schema не меняются. Не добавляется полное дерево навыков в публичный клиент. Один skill ID всегда имеет одну кривую независимо от источника изучения.

Редактор поддерживает фильтр профессий, табличную правку, наследование, undo/redo и тестовый уровень навыков с ограничением по собственным максимумам. Уменьшение cap/порогов не запускает скрытую миграцию сохранений: несовместимость указывается при загрузке с ID навыка. Тестовые сессии используют чистые БД.

## Категории и рабочее место — 2026-10-10

Улучшение интерфейса одобрено пользователем после плана категорий, отдельных форм профессий и тестовой площадки. `EditorSchema` и `EditorLabels` в Balance.Core задают единый каталог страниц, полей, единиц, подсказок и предварительных ограничений. Они не подменяют серверную валидацию или игровые формулы. Новые числовые определения подключаются через метаданные, а не отдельные расчётные реализации в UI.

Godot-оболочка разделена на навигацию, инспектор, таблицы уровней, тестовую площадку и сравнение. Категории отображаются деревом; поиск учитывает названия параметров, фильтры — избранное и изменения. JSON-черновик поддерживает возврат отдельных полей/карточек, сравнение с сохранённым исходником и атомарные операции диапазона таблицы с одной отменой. Вставка ограничена размером и валидируется до замены таблицы.

Настройки рабочего места и именованные билды хранятся в отдельном versioned local JSON `.artifacts/balance-studio/workspace.json`. Это удобство автора, не мировой persistence и не content definitions. Smoke-сценарии не читают и не перезаписывают пользовательские настройки. Не добавляются роли, права доступа, GM-журнал или новые сервисы.

## Тестовая площадка

`BalanceSession` фиксирует снимок черновика и билд на момент нажатия. Создаёт уникальную `.artifacts/balance/<session>/`, собирает туда сервер, сохраняет копии content/regions/build и запускает отдельную SQLite БД на свободном UDP-порту. Затем запускает обычный игровой клиент с отдельной Development identity.

Серверные startup options `Balance:ContentPath`, `Balance:BuildPath`, `Balance:RegionsPath` разрешены только в Development. Они не являются игровыми пакетами. После загрузки каталога/регионов `BalanceTestBuild` готовит только начального тестового персонажа; существующие сохранения не переписываются. Тестовый персонаж появляется у арены с выбранными stats/level/weapon/profession, корректными источниками навыков и уникальными item UUID. Для сравнения крайних значений разрешён явно показанный сверхлимит очков в тестовом билде.

Манекены в тестовой копии получают параметры выбранного существа, сохраняя поведение манекенов. По флажку добавляется один обычный AI-противник выбранного типа. Выбор статов босса не запускает специальную логику boss encounter. Пользовательские сценовые placements не меняются.

Необязательный `SelectedAbilityId` в Development-билде назначает выбранный уже изученный навык на Q. Сервер проверяет принадлежность стартовому набору/выбранной профессии, исключает рывок и переставляет слоты без дубликатов. Для подготовки теста не требуется новый игровой пакет или выдача скрытых навыков публичному клиенту.

«Применить и играть» перезапускает только принадлежащие мастерской тестовые процессы с новой базой. Это быстрый чистый повтор опыта, а не замена каталога посреди текущего каста. Артефакты сессий сохраняются для разбора; рабочая `.data` не используется. При закрытии редактора его тестовые процессы завершаются.

## Alternatives considered

1. Только ручной JSON/CLI: небольшой объём, но нет удобных форм и подготовки игрового билда.
2. Сначала полное выделение Rules, разделение JSON, новый протокол всех описаний и release manager: полезно в дальнейшем, но не нужно как предварительное условие локального инструмента.
3. Отдельный Godot tools-проект и переиспользование Server — выбрано. Компромисс: Core зависит от серверной сборки и её транзитивных .NET-зависимостей; будущая декомпозиция может убрать этот coupling без изменения файлов данных или игрового клиента.

## Consequences / verification

Игровой протокол и persistence schema не меняются. Новые startup fixture options не доступны из игрового UI. Файловая работа, сборка и отчёты выполняются вне server tick. Public client не получает серверные определения.

Проверяем совпадение preview с настоящим ServerWorld, загрузку профессий/предметов, сохранение precision, undo/redo, конфликт внешних правок, отказ записи невалидного каталога, GUI smoke и настоящий UDP-клиент с изменённым навыком. Команды и результаты — в [руководстве](../development/balance-workshop.md).

## Deferred

Полный rules extraction, создание новых ID/механик, редактирование AI/региональных сцен, ротационный симулятор, полноценные динамические числовые описания всех навыков/пассивок, hot reload работающего мира и все инструменты ГМ. Они не объявляются частью готовой первой мастерской.

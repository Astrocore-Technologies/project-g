# ADR 0014: Рельеф регионов и общие подземелья

## Status

**Принято направление мира, 2026-10-10.** Пользователь подтвердил предложенную
схему «как в Albion»: высоты внутри региона и переход в общее подземелье.
Backend навигации, его числовые пределы и миграция ещё не выбраны; они проходят R7.
Этот документ не означает, что рельеф или новое подземелье уже работают в игре.

Первый исследовательский блок R7 реализован и проверен 2026-10-10:
[сцена и измерения](../development/navigation-study.md),
[рекомендация полигонального backend](0015-navigation-study-recommendation.md).
Окончательная приёмка backend и оставшиеся R7/R8 проверки ещё впереди.

Связанные решения: ADR 0001, 0004, 0011, 0012;
[gameplay contract](../design/gameplay-contract.md),
[план регионов](../../.codex/region-scenes-plan.md).

## Context

В текущем прототипе server movement, snapshots, AI и combat используют X/Z.
NavigationGrid хранит одну плоскую маску; FlatGeometryBake принимает проходимые
axis-aligned boxes с верхней поверхностью на Y=0. Установка Terrain3D не меняет
серверные координаты, маршруты или проверки попаданий.

Требуются холмы, впадины и склоны, а также общие открытые подземелья, куда игрок
входит из мира. Возможный проход под мостом нельзя выразить одной картой высот.
Albion — ориентир поведения и организации локаций. Его закрытый серверный код
и конкретный navigation backend не считаются известными или скопированными.

Сохраняются Godot client / независимый .NET server / Shared, LiteNetLib,
fixed tick, server authority, single shard и текущая database strategy.
Новые worker/service boundaries этим решением не вводятся.

## Decision

### Регионы и подземелья

- Холм, склон, впадина и рампа находятся внутри региона: их прохождение не
  запускает загрузку другой локации.
- Пещера/подземелье подключается физическим входом к общему региону через
  существующую модель server-owned travel. Допускается короткая загрузка сцены.
- Несколько входов могут вести в один регион. Destination выбирает сервер
  по разрешённому route и entry, а не по переданному клиентом имени локации.
- Игроки разных групп попадают в одну территорию и разделяют её world state,
  мобов и предметы. Вход не создаёт копию для персонажа или группы.
- Глубокие уровни первой версии можно разделить на общие регионы с переходами
  на лестницах/в дверях. Подземелье не обязано геометрически лежать под наружной
  картой. Каждый такой уровень — отдельное место, не канал одной территории.
- Непрерывные этажи, мосты над проходами и балконы внутри региона требуют
  нескольких различимых поверхностей. Не заменяем их декоративной высотой
  поверх плоских проверок движения/боевых попаданий.

Вход в подземелье не меняет PvP policy, loot ownership, respawn delays или
сохранённые cooldown. Правило travel при combat tag остаётся отдельным D3
из ADR 0012: разрешение этой схемы не выбирает неуязвимость при загрузке.

### Геометрия и ответственность

| Область | Требуемое поведение |
| --- | --- |
| Client / editor | Редактируемая сцена; выделенные walkable surfaces, blockers и combat occluders; выбор нужной поверхности кликом; отображение высоты и prediction |
| Server | Разрешённая поверхность, высота, маршрут и переходы; authoritative NPC и movement; проверки range/shape/LOS без попадания через перекрытия |
| Shared | Только публичная ограниченная геометрия и детерминированные queries/movement, versioned IDs/DTO; без Godot и скрытых rules |
| Database | Region/map revision и достаточная информация для восстановления положения на нужной поверхности; explicit migration legacy saves |

Высоту тела нельзя принимать на веру из клиентского результата движения.
Click intention задаёт точку и однозначную поверхность; сервер проверяет её
существование, доступность и принадлежность региону/revision. Точный wire layout
определяется после выбора backend, не объявляется уже поддерживаемым.

Проходимость и видимость для атак — разные queries. Блокер движения не обязан
быть непрозрачной бесконечной стеной для снаряда. Модель должна отличать склон,
обрыв, стену и перекрытие, поддерживать разные поверхности на одинаковых X/Z.
Размеры/профили акторов и ограничения slopes/clearance задаются в данных.

### Порядок реализации

1. R7: сравнить bounded tiled surface grid и offline polygon navigation с
   независимыми .NET queries. Сцена проверки: плоская площадка, холм со склоном,
   впадина, непроходимый обрыв, узкий проход и мост с проходом под ним.
2. После измерений зафиксировать backend, bounds, quantization, surface identity,
   revision semantics и migration strategy отдельным уточнением ADR.
3. R8: первый интегрированный сценарий «клик → подъём на склон → спуск» для
   двух клиентов и NPC, включая authoritative snapshots, prediction и reconnect.
   До его приёмки новая геометрия не публикуется в рабочие карты.
4. Следующий сценарий: игрок и цель на разных высотах, открытая линия атаки и
   закрывающая её геометрия. Затем мост/нижний проход с независимыми маршрутами.
5. После R4/R6: вход в общее тестовое подземелье и возврат, два игрока из разных
   групп, одно состояние региона; при необходимости второй общий уровень.

Сравнение R7 не требует заранее менять игровой протокол или рабочую БД.
Интегрированная поддержка высоты потребует согласованного version bump:
protocol/content/export, snapshot batching и versioned save models.

## Alternatives considered

### Размещение мира

| Вариант | Complexity / ops / scaling | Latency / Mobile | Testability / migration / failure modes |
| --- | --- | --- | --- |
| Общие регионы с рельефом, подземелья через входы — принят | Развивает существующие region ownership и AOI, без нового процесса | Короткая загрузка на входе; ограниченная память активной сцены, transient old/new resources измеряются | Проверяемые gates/arrivals/revisions; отдельные failure/recovery проверки загрузки; legacy flat mapping только explicit |
| Непрерывный объём с наружным миром и всеми подземными этажами | Требует вертикального streaming, сложнее геометрия/интерес и lifecycle; сам по себе не увеличивает server capacity | Нет обязательного входного load, но больше cache/occlusion/streaming работы на клиенте | Более сложны selection, LOS, overlapping surfaces и сохранённые координаты; неверный уровень может отправить игрока на другую поверхность |

### Навигация — выбор отложен до измерений

| Кандидат | Complexity / scaling / ops | Latency / Mobile | Testability / migration / failure modes |
| --- | --- | --- | --- |
| Bounded tiled grid с несколькими поверхностями и явными связями | Близок к текущим queries; память зависит от площади/разрешения; нужны bounded tile graph и search budgets | Простая prediction parity; измерить размер relevant tiles и path CPU | Детерминированные .NET fixtures; риск потерять узкий проход/clearance при rasterization, недопустимо молча выбирать верхний пол |
| Offline exported polygon navigation с surface IDs | Компактнее открытые пространства; сложнее export, clearance, smoothing и dynamic patches | Измерить query CPU, tile delivery и клиентский cache | Независимые .NET fixtures; риск несовпадения baked polys и collision; legacy mapping/revisions всё равно нужны |

## Consequences

Один scalar height на X/Z годится для части наружного рельефа, но не является
достаточным общим контрактом. Физическая поверхность и region identity должны
оставаться различимыми при последующих этажах; это не gameplay layer/shard.

До публикации вертикального контента требуется решить и проверить сохранённые
позиции/ground items/spawns/gates, выбор кликом, NPC/auto-approach, melee/projectile/AoE,
dash, combat-logout bodies, exploration/AOI и визуальные occlusion/camera сценарии.
Простая смена Vector2 на Vector3 не закрывает эти зависимости.

Профилируем export size/time, path CPU/allocations, queries per tick, relevant
geometry bandwidth, snapshot size и Mobile peak memory. Global scans и передача
всей геометрии каждому игроку не являются допустимым способом реализации.

## Migration / rollout

Принятое направление и исследование R7 не меняют рабочий runtime, протокол и сохранения.
Рабочие authored scenes продолжают использовать нынешний flat export.

Будущий rollout сначала проходит на isolated fixture maps и копии SQLite.
Legacy X/Z получают высоту/поверхность только через известный mapping региона
и revision. Не выбираем поверхность эвристически, если несколько этажей имеют
одинаковые X/Z. Неизвестная версия fail closed; progress/items не сбрасываются.
Incompatible persistence migration и политика восстановления утверждаются
отдельно до применения к рабочей БД.

## Deferred

- Окончательный navigation backend, числовые размеры tiles/search/memory budgets.
- Формула дистанции атак по поверхности/в пространстве и vertical reach melee/AoE.
- Бонусы урона/дальности от высоты, прыжки, падение и его последствия.
- Непрерывное размещение всего подземелья под наружной картой.
- Dungeon reset/replay, новый loot/PvP/respawn balance, combat-loading policy D3.

## Verification

Первоначальное принятие направления было документационным. Затем выполнен
первый блок R7: build решения, 41 navigation test, headless export и графический
Godot preview. Результаты и границы — в [отчёте](../development/navigation-study.md).
Рабочий multiplayer gameplay с высотами и оставшиеся R7/R8 проверки ещё впереди.

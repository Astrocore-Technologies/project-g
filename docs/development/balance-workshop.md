# Локальная мастерская баланса

## Запуск

Из корня проекта:

```powershell
./tools/Open-BalanceStudio.ps1
```

Скрипт собирает solution и открывает отдельный редактор. Godot .NET ищется в `GODOT_PATH`, PATH или установленном каталоге Godot на диске проекта. Явный путь:

```powershell
./tools/Open-BalanceStudio.ps1 -GodotPath D:/Godot_v4.7.1-stable_mono_win64/Godot_v4.7.1-stable_mono_win64_console.exe
```

Можно открыть `tools/BalanceStudio/project.godot` в Godot .NET и нажать F5 после сборки .NET-проекта. Это отдельный tools-проект; основной игровой project.godot не меняется.

## Работа

1. Слева раскрыть нужную категорию: **Персонаж**, **Уровни и опыт**, **Бой и защита**, **Профессии**, **Общие навыки**, **Оружие и экипировка**, **Существа**. Поиск понимает название, ID и название параметра: например, «кровотечение» находит навыки с таким эффектом.
2. Изменить число и нажать Enter либо выйти из поля. Справа обновится сравнение «до / после». Ошибка каталога показывается сразу; исправить можно в той же форме.
3. Открыть **Тестовую площадку** кнопкой «Тестовый билд»: настроить уровень, шесть статов, профессию, оружие, цель и навык на Q. Пресеты 1/15/30 вкладывают доступные очки в STR; затем распределение можно изменить вручную. Отрицательное число свободных очков явно обозначает тестовый сверхлимит. Вкладка «Сохранённые билды» позволяет сохранить набор под именем, загрузить или сравнить его с текущим.
4. «Сохранить» записывает проверенный баланс в открытый исходник. «Копия…» сохраняет отдельный JSON. Стрелки отменяют/повторяют правки.
5. «Применить и играть» использует текущий черновик даже без сохранения исходника. Откроется обычная игра у тренировочной арены с подготовленным персонажем. Навыки выбранной профессии уже изучены; снаряжение надето.
6. Манекены используют статы выбранной цели. Флажок добавляет подвижного противника с обычным AI. Для проверки специального поведения босса нужна отдельная сцена/настройка encounter.
7. После следующей правки снова нажать «Применить и играть»: прежняя тестовая сессия завершится, новая запустится с чистой БД. «Стоп» завершает только процессы, созданные редактором.

Сборка тестового сервера выполняется автоматически в отдельный output. Все копии, SQLite и сборка лежат в `.artifacts/balance/<session>/`; каталог не входит в Git. Эти файлы не очищаются автоматически. Рабочий персонаж в `.data/project-g-development.db` не используется.

### Навигация и безопасное редактирование

- Звёздочка у заголовка добавляет страницу в избранное; фильтры слева показывают избранные или изменённые страницы. Поиск учитывает параметры и работает вместе с фильтрами.
- Изменённые поля выделены. Стрелка рядом с полем возвращает только его; «↶ Вернуть» в заголовке карточки — всю карточку. Точка возврата — открытый файл или последнее сохранение, а не заводской баланс. Возврат можно отменить.
- «Изменения» показывает отличия от сохранённого баланса и переходы к настройкам. Проценты показаны с одним знаком; точные значения — в подсказке.
- Ctrl+S — сохранить, Ctrl+Z/Ctrl+Y — отменить/повторить, Ctrl+F — найти, Tab — перейти к следующему полю. Внутри текстового поля действует также его обычная отмена ввода.
- Ошибки ввода показаны у поля; ошибки сочетания параметров проверяет серверный загрузчик. Сохранение и запуск недоступны для невалидного каталога. Некорректный тестовый билд блокирует запуск, но не сохранение корректного баланса.
- Ширина дерева меняется разделителем. «Сравнение» скрывает правую панель, «Журнал запуска» раскрывает логи. Заголовок и вкладки не прокручиваются вместе с формой.
- Выбранная страница/вкладка, свёрнутые ветки, прокрутка, ширина дерева, избранное, текущий и именованные тестовые билды сохраняются локально в `.artifacts/balance-studio/workspace.json`. Это не игровой баланс, не сохранение персонажа и не файл для публикации. Именованные билды записываются сразу, состояние окна — при закрытии.

## Что показывают расчёты

HP, мана, реген, урон автоатаки после защиты, интервал, ожидаемый DPS с критами, крит/блок и HP цели. Для выбранного melee-навыка — прямой урон выбранного уровня, стоимость и cooldown. Время задано в секундах, дальность в метрах. DPS не учитывает движение, блок, промахи, временные пассивки и ротацию.

Игровые числа округляются для отображения, проценты — до одного знака. Расчёты и нетронутые коэффициенты сохраняют точность. Наведение на числовое поле показывает путь и точное исходное значение; на результат — точный урон/реген.

При редактировании файла снаружи сохранение сообщает конфликт и не затирает внешний файл. Сохраните свой черновик отдельной копией; затем откройте актуальный файл, подтвердив отказ от несохранённых правок при необходимости.

## Профессия → навык → уровни

Дерево **Профессии → Мечник** содержит обзор и получение, активные навыки, пассивки и рывок. В **Обзор и получение → Получение профессии** находятся условия открытия, требуемый урон и дистанция разговора с тренером. Отдельного пункта «Обучение у тренера» больше нет. Пять пассивок разбиты на именованные карточки с пояснениями. «Общие навыки» показывает навыки вне наборов профессий; обычный рывок находится в «Бой и защита».

Восстановление манекена находится в **Существа → Манекены → Манекен → Настройки → Восстановление**. Это задержка полного восстановления после разрушения, не регенерация в бою. Перенос затрагивает только размещение полей редактора: их серверные пути `swordsman/requiredDamage`, `interactionRange` и `dummyResetSeconds` сохранены. Поиск, список изменений и возврат карточки используют эти же значения без дублирования. Сохранённый выбор/избранное старой страницы обучения переводятся на страницу профессии при открытии мастерской.

Специальные навыки босса находятся в **Существа → Боссы → Босс → Навыки**, а не в «Общих навыках». Карточка босса содержит вкладку «Навыки» с переходами к их параметрам; те же навыки раскрываются дочерней веткой босса в дереве. Состав берётся из `creatures[].abilityIds`, числовые значения по-прежнему сохраняются в `abilities[]`. ID страниц не меняются, поэтому поиск/избранное/изменения продолжают работать. Навык, доступный также игроку, остаётся в своём общем или профессиональном разделе и доступен по ссылке у босса. Один NPC-only навык нескольких боссов имеет один редактор под первым владельцем и ссылки из остальных. Навык босса нельзя назначить на Q тестового персонажа.

- «Основное» — урон, перезарядка, стоимость ресурсов; «Попадание» — дальность/радиус/угол; «Эффекты» — существующие параметры эффектов. Пустые вкладки не показываются. «Связи» — профессии, использующие существа и неизменяемые требования механики.
- «Прокачка» — свой максимум, практика за успешное применение и таблица переходов. Например, строка уровня 2 с практикой 50 означает 50 единиц для перехода 2 → 3. Последняя строка всегда имеет нулевую стоимость: это максимум. «Всего» показывает накопленную практику от первого уровня; «Урон» — прямой урон ближнего приёма для текущего тестового билда на каждом уровне.
- «Сила · %» — 100,0% от базового урона, 170,0% — в 1,7 раза больше. Она масштабирует прямой/магический урон и кровотечение в тех же местах, где раньше действовал общий прирост. У рывка меняет скорость, а не расстояние. «Перевести дух» пока использует фиксированное восстановление выносливости из параметров приёма.
- Таблицы независимы для разных ID навыков. Общий навык с тем же ID в двух профессиях остаётся одним навыком с одной таблицей.
- «Общая формула» удаляет отдельную таблицу: навык снова наследует `progression.practicePerLevel`, `skillLevelCap`, `powerPerSkillLevel`. Первая правка наследуемой таблицы создаёт собственную копию. «Вернуть таблицу» восстанавливает сохранённую. Undo/redo работает для всех этих действий.
- Изменение максимума сохраняет существующие строки. При увеличении новые уровни получают силу прежнего максимума и стоимость по общей формуле; их можно сразу отредактировать. При уменьшении последние строки удаляются из черновика; undo их возвращает.
- На тестовой площадке уровень навыков задаёт уровень всех изученных навыков тестового персонажа. Каждый ограничивается собственным максимумом. Эти же уровни используются в сравнении урона.
- Кнопка «Поставить на Q в тестовом билде» на вкладке «Основное» выбирает навык, его профессию и подходящий меч. При следующем запуске сервер назначает изученный навык в первый слот; неизвестные персонажу навыки и рывок сюда не допускаются.
- «Диапазон / вставка…» раскрывает групповое редактирование: выбрать уровни и колонку, заполнить одним значением или изменить на процент (10 = +10%, −10 = −10%). Практика при умножении округляется до целого. Копирование/вставка используют две колонки с Tab: практика и сила в процентах, совместимые с таблицами. Весь диапазон проверяется и отменяется одним действием; частичная вставка при ошибке не происходит.

Данные сохраняются в `Content.Server/Data/prototype.json`, `abilities[].progression`: `practicePerUse` и `levels[]` с `practiceToNext`/`powerMultiplier`. Сила хранится долей (1,7), показывается процентами (170,0%). Максимум — число строк. Таблица ограничена 1000 уровнями; большие таблицы разбиты на страницы в редакторе. Старые каталоги schema 3 открываются с прежней формулой, при добавлении таблицы черновик становится schema 4. В штатном файле все 11 навыков профессий получили собственные таблицы с прежним балансом.

Игровой протокол и формат сохранения персонажа не менялись. Сервер сохраняет уровень и накопленную практику, начисляет её только за прежние подтверждённые успешные применения и переносит остаток при повышении. Изменение таблицы не переписывает существующую БД: сохранённый уровень выше нового максимума или практика не меньше нового порога требуют отдельного решения о миграции. Для экспериментов кнопка запуска всегда создаёт чистую тестовую БД.

## Границы первой версии

- Формы редактируют существующие числовые параметры. Создание нового типа навыка/профессии, изменение ID, bool-механик и ссылок требует работы с контентом/кодом.
- Одновременно активна одна тестовая сессия редактора; её повторный запуск создаёт нового тестового персонажа.
- Это перезапуск теста, не live reload. Обычный сервер после сохранения баланса по-прежнему нужно пересобрать/перезапустить.
- Числовые описания умений и пассивок в игровом UI ещё содержат старые авторские строки. При тестировании изменённого баланса ориентируйтесь на мастерскую и подтверждённый урон; HUD показывает текущие серверные cost/cooldown. Полная замена числовых текстов на server parameters — следующий самостоятельный UI/protocol шаг.

# Высоты, бой и общее подземелье — интеграционный срез

2026-10-10. По разрешению пользователя подключены authoritative высоты к обычной
игре. Дальность — прямое расстояние в 3D без бонусов высоты; combat tag запрещает
переход в любой регион, включая подземелье. Это две небольшие редактируемые карты
для проверки основы будущего мира. Лор и постоянное наполнение здесь не задаются.

## Где редактировать и как пройти

- `Content.Client/Scenes/Regions/TerrainTest/TerrainTest.tscn`: холм +4 м, впадина
  −3 м, мост +4 м с нижним проходом, обрыв и узкий проход.
- `Content.Client/Scenes/Regions/DungeonTest/DungeonTest.tscn`: общий нижний зал
  и галерея +4 м, соединённые пандусом. Пандус должен физически касаться площадки.
- Маршруты, arrivals, NPC и манекен: `Content.Server/Data/regions.json`.
  В старом регионе `prototype` вход на стенд расположен X=−20, Z=18.
  На стенде вход в подземелье X=16, Z=14; обратный выход X=−17, Z=14.
  Возврат ведёт на безопасную точку вне входного триггера.
- В обычном Development-запуске сервера изменённые сцены экспортируются
  автоматически через прежний `tools/Export-Regions.ps1`. Ручной шаг перед игрой
  не нужен. Экспорт не переписывает сцены или ручные правки.
- `res://Tests/Regions/TerrainLiveSmoke.tscn` проверяет настоящую игровую сцену:
  RMB, холм, мост, впадину, подземелье, галерею и возвращение. Ему нужен отдельный
  сервер с `Server:StartingRegion=terrain_test`, отдельной SQLite и новым тестовым
  профилем. В прогоне используется отдельный fixture regions.json со скоростью
  12 м/с и отключёнными NPC, чтобы проверка маршрута не зависела от боя.

## Что делает runtime

Godot один раз запекает геометрию при экспорте. Native polygons и OBB препятствия
попадают в публичный `Data/Regions/surface-package.json`. Сервер не использует
Godot: общие bounded queries определяют поверхность, связность, путь и LOS.
Рёбра сопоставляются по полным XYZ; этажи на одинаковых X/Z не соединяются.
Клиентское prediction, replay и серверный fixed tick используют один solver.
Скорость расходуется на длину в 3D, включая подъём и спуск.

MoveCommand передаёт цель X/Z, высоту выбранной поверхности и geometry hash.
Высота — намерение, которое сервер проверяет и приводит к своей геометрии.
Spawn/snapshot включают подтверждённую высоту; snapshots идут прежним частым
ненадёжным каналом. Текущий Protocol 33 включает геометрию предпросмотра навыков и несовместим с прежним wire layout. При envelope
1200 bytes batch содержит максимум 21 entity по 56 bytes.

NPC и Эхо двигаются по поверхностям; snapshots и интерполяция отображают высоту.
Рывок следует прямому связанному коридору поверхности и не переносит на другой
этаж через перекрытие. Повторный клик с чуть отличающейся высотой не перезапускает
уже построенный маршрут.

Обычный удар, melee skills и cast range используют Euclidean 3D. Projectile
имеет нормализованное XYZ направление и swept hit; стена/перекрытие обрывают
полёт. Ground area и подпись Эхо проверяют реальную поверхность центра,
трёхмерный радиус и LOS до жертвы. AOI broad phase остаётся X/Z и не определяет
попадание. Тесты отдельно проверяют открытую линию вверх и закрытый мостом этаж.

Сохранения персонажа, Эхо и death loot получают аддитивный `SavedSurface` v1:
высота и hash точного экспорта. Старые плоские сохранения остаются допустимыми.
На вертикальной карте отсутствие или неизвестный hash отклоняются: сервер не
угадывает верхний/нижний пол и не сбрасывает прогресс. Изменение такой карты для
уже сохранённых персонажей требует известного mapping/migration. Рабочая БД
не мигрировалась для этой проверки; использованы отдельные SQLite fixtures.

## Переход и восстановление

Подземелье — один общий регион для игроков любых групп. Каждому входящему
персонажу не создаётся копия. Ownership и durable перенос сохраняются через
существующий checkpoint с fencing; runtime entity ID может меняться, PlayerId,
CharacterId, inventory и progression сохраняются.

Текущий порядок: commit destination → новый epoch + geometry → client scene-ready
→ authoritative baseline → client applied → server activation. До activation
клиент и сервер блокируют gameplay intentions. Неверный hash и старый epoch не
активируют персонажа. Геометрия передаётся bounded ReliableOrdered chunks по
900 bytes, до 256 KiB; assembly одна на epoch. Timeout загрузки — 30 секунд,
после обрыва персонаж восстанавливается из сохранённого destination.

При обычном входе loading actor не становится целью атак до activation.
При reconnect с действующим combat tag прежняя уязвимость сохраняется;
загрузка не снимает tag. Начало любого travel при tag запрещено, и возле
выхода клиент показывает причину. Preload destination до commit, полноценный
двухсценный loading screen и остальные требования R4 остаются отдельной работой.

## Проверка и оставшиеся границы

Команды проверки: `dotnet build Game.slnx --no-restore -m:1`, полный
`dotnet test Content.Tests/Content.Tests.csproj --no-build --no-restore`,
export + `--validate-content`, `tools/Export-Regions.ps1 -CheckOnly -NoBuild`,
графический Godot Mobile/D3D12 прогон `TerrainLiveSmoke`.

Финальный прогон: build успешен; 628 tests passed, 7 skipped, 0 failed
(635 total). Графический smoke завершился `TERRAIN_LIVE_OK`; экспорт обеих
карт и server content validation прошли. Семь skipped проверок требуют внешней
PostgreSQL либо явно подключённой копии пользовательской development-БД.

Сценарии включают одинаковое movement/prediction по четырём маршрутам, сохранение
и восстановление пола, неверный hash/NaN, дальность 10 м при высоте 8 м,
перекрытие и реальный pitched projectile, задержанную readiness, две lossy
UDP сессии в одном подземелье и возвращение с тем же inventory/PlayerId.
Live PostgreSQL и проверка пользовательской development-БД не включены без
соответствующих fixture/environment settings.

Большая связная карта, funnel smoothing, tile packaging/AOI cache, нагрузка,
native Mobile memory/GPU, много-региональный fog по этажам и dungeon reset/replay
этим срезом не объявляются готовыми. Полигональные пути пока проходят через
середины порталов; их безопасность проверена, но плавность предстоит улучшить.

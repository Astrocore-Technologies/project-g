# Буковая долина: запуск и редактирование

Переработанная область Линвеля занимает **1000 × 1000 м**. Земля хранится в
редактируемом Terrain3D; Blender используется для отдельных ассетов.
Основной проход — 1102,901 м, расчётно **5:15** без остановок при 3,5 м/с.
Это длина центральной линии по поверхности: игрок может срезать часть пути.

Концепция: `docs/design/linvel-beech-valley-blueprint.md`.
Результаты и ограничения: `docs/development/linvel-beech-valley-acceptance.md`.

## Осмотр без сервера

Открыть `Content.Client/Tests/Regions/LinvelBeechPreview.tscn` и нажать **F6**.
1–5 показывают двор лесных промыслов, Буковый мост, светлый гребень,
углежогные террасы и дальнюю поляну. 6 — лесная тропа, Tab — общий план,
стрелки — перемещение камеры. Капсула обозначает масштаб; это осмотр
окружения, а не сетевое управление. Камера: offset `(0,24,24)`, FOV 50.
Такой же обзор используется камерой игрока. Саму `BeechValley.tscn` также
можно запускать через F6: её `RegionPreviewCamera` предназначена для осмотра.
При сетевой загрузке клиент удаляет эту отмеченную камеру и явно привязывает
Terrain3D к камере локального игрока до включения физического обновления.
Общий план отключает туман и дальнее отсечение; его нагрузка отличается
от обычной игровой камеры.

## Где редактировать

Пути без `Content.*` в таблице относятся к `Content.Client`.

| Файл или узел | Назначение |
| --- | --- |
| `Tools/Linvel/BeechValleyRevision2.tscn` | Сохранённая сцена авторинга, явные инструменты и источник Proton Scatter |
| `Scenes/Regions/Linvel/BeechValley.tscn` | Публичная игровая сцена без генератора окружения |
| `Geometry/Terrain` | Рельеф, покраска и физическая поверхность Terrain3D |
| `Assets/World/Linvel/Beech/Revision2/Terrain/DataFinished` | Активные нативные высоты и покраска: четыре региона 256², spacing 2 м |
| `Assets/World/Linvel/Beech/Revision2/Terrain/beech_assets.tres` | Четыре материала панели текстур Terrain3D |
| `Assets/World/Linvel/Beech/Revision2/Terrain/beech_material.tres` | Материал и стилизованное освещение земли |
| `Places` | Пять редактируемых композиций и их центры |
| `Exploration` | Восемь исследовательских ответвлений |
| `EncounterMarkers`, `EncounterEnvironment` | Резервы боевого наполнения и физические укрытия |
| `Woodland`, `LandmarkTrees`, `ComposedForestEdges` | Деревья и группы на выходах камня |
| `AuthoredForestBands` | 210 дополнительно размещённых деревьев в шести лесных группах |
| `AuthoredForestRegrowth` | 407 отдельно редактируемых низких кустов; без коллизий |
| `Understory`, `TrailDetails` | Сохранённая растительность и детали выбранных участков |
| `Assets/World/Linvel/Beech/Revision2/Prefabs` | Ассеты библиотеки Asset Placer |
| `Content.Server/Data/regions.json`, `linvel_beech` | Серверные переходы, спавны и публичные ориентиры |

Визуал и `StaticBody3D/CollisionShape3D` находятся под одним корнем ассета
и перемещаются вместе. У мелкой растительности, предметов и воды нет лишних
коллизий. Физический слой 1 — выбираемая поверхность; слой 3, значение 4 —
непроходимые предметы.

Сначала редактировать и сохранять сцену авторинга. Для публикации вызвать
`Authoring.publish_revision()` через Godot MCP. Метод сохраняет копию без
служебного инструмента и источника scatter. Он не запускается автоматически.
Ручные правки публичной сцены сначала перенести в авторинг: следующая явная
публикация заменит её сохранённой копией авторинга.

Terrain3D редактируется штатными кистями. Завершённые действия инструмента
защищены metadata от повторной генерации; не снимать guards поверх ручных
правок. Старые каталоги Terrain-данных сохранены как промежуточные источники.
Активен `DataFinished`; переключение на промежуточный каталог не обновляет карту.

## Ассеты и материалы

Исходник: `art-source/linvel/beech/revision2/beech_revision2_assets.blend`.
В комплекте 23 собственных GLB и нативных meshes: семь вариантов бука,
молодняк, низкий подлесок с объёмными листьями, камни, мост,
навесы, углежогная печь, растения и рабочие предметы. Часть прежних небольших
предметов переиспользована. Модели создавались через Blender MCP; единицы —
метры, glTF экспортируется с Y вверх. Происхождение:
`art-source/linvel/beech/revision2/provenance.json`.

Активный набор текстур — `Revision2/StylePass`: два собственных рисованных
атласа и восемь текстур 512² с mipmaps. `GroundGrass` задаёт мягкие пятна
зелени, мха и почвы без нарисованных пучков травы. Объёмная растительность
редактируется отдельно в сцене. `GroundPath`, `GroundRock`, `DampSoil` доступны
в панели Terrain3D; высоты и существующая покраска не менялись ради текстур.
RGBA-альфа этих четырёх материалов — нейтральная высота смешивания 0,5,
а не прозрачность. Переходы материалов плавные, повтор цвета зеркальный,
чтобы на широких живописных пятнах не появлялись резкие стыки тайлов.

`LeafClusters` и `SilverBark` используются общим `painted_forest.tres`.
Листва получает плавную трёхосевую проекцию вместо швов между гранями.
Шейдер скрывает мешающие кроны целиком с переходом через непрозрачный dither;
круглый тоннель через листву убран. Коллизии стволов сохраняются.
`WaterColour` и `WaterFoam` задают крупные движущиеся рисованные полосы воды.
`Geometry/ForestStream` — сохранённый `ArrayMesh`; вода переживает закрытие
редактора и не имеет отдельной коллизии. Прежний `ImmediateMesh` не сохранял
геометрию русла. Первые текстурные атласы сохранены как промежуточные источники;
активные материалы ссылаются на `StylePass`.

## Экспорт после правок

После изменения рельефа, предметов, коллизий или маркеров выполнить:

```powershell
./tools/Export-Regions.ps1 -GodotPath 'D:/Godot_v4.7.1-stable_mono_win64/Godot_v4.7.1-stable_mono_win64_console.exe'
```

Экспорт валидирует кандидат до публикации. Не запускать два экспорта
одновременно. При изменении дорог обновить публичные образцы маршрутов
из разметки через инструмент авторинга; их нельзя отключать ради скрытия ошибки.

Bake: cell size 1 м, cell height 0,05 м, agent radius 0,45 м, height 1,8 м,
detail distance 6, detail error 4. Recast округляет радиус до целой ячейки.
Экспорт сохраняет топологию Recast, уточняет высоты по Terrain3D и реальным
настилам, затем локально делит грани для точности дорог. Terrain3D остаётся
источником редактирования.

Статический бюджет — **16 384 вершины, 16 384 суммарные грани, 1 МиБ**;
256 объёмных LOS-преград. Формат 3 добавляет непроходимые грани крутых
склонов и замкнутые грани 344 физических стволов: они перекрывают атаки,
но не создают проходимый этаж. Стволы не расходуют отдельный объёмный LOS
слот; их грани входят в тот же ограниченный бюджет. Клиент и
сервер обновлять вместе: протокол подключения **35**. Статические чанки —
900 байт, частые пакеты сохраняют предел 1200 байт.
Обоснование — `docs/architecture/0016-static-region-geometry-budget.md`.

## Настоящий клиент и сервер

Для самостоятельного теста использовать свободный порт и отдельную БД:

```powershell
dotnet run --project Content.Server -- --environment=Development --Server:Port=19071 --Server:StartingRegion=linvel_beech --Persistence:SqlitePath=D:/projects/project-g/.artifacts/linvel-beech-playtest/world.db
```

Во втором терминале:

```powershell
& 'D:/Godot_v4.7.1-stable_mono_win64/Godot_v4.7.1-stable_mono_win64_console.exe' --path Content.Client res://Scenes/World.tscn -- --server-port=19071 --identity=linvel-beech-playtest
```

Для автоматической проверки использовать
`res://Tests/Regions/LinvelBeechLiveSmoke.tscn`: физические RMB-клики,
авторитетное движение, высота фигуры и сравнение LOS через дерево, перила
и склон. Перед запуском собрать клиент.

Обычный Development-сервер начинает в Садовых долинах. Текущий граф включает
Садовые долины, Буковую долину и Лисьи холмы. Удалённые тестовые сцены
не возвращаются в игру; legacy-тесты используют отдельные fixtures.
Сохранения со старым region ID или surface hash не мигрируются молча.
Рабочую БД нельзя подменять тестовой.

По указанию пользователя от 14 октября новых мобов и AI в этот проход не
добавляли. AI, Рагур, награды и игровые условия исследования не объявляются готовыми
по наличию разметки: Blueprint выделяет их в отдельный согласованный проход.

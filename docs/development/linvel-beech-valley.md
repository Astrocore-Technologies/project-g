# Буковая долина запуск и редактирование

Первая игровая итерация наружного региона Линвеля: рельеф, лес, промысловые
места и проход через мост. Размер 960×800 м; ломаная основная тропа — 1509,9 м,
то есть около 7:12 чистой ходьбы при 3,5 м/с. Это расчёт по центру тропы, а не
измерение маршрута каждого игрока: свободное движение позволяет срезать часть пути.
Город, остальные области котловины и выход из ущелья этим участком не реализованы.

## Осмотр без сервера

Открыть `Content.Client/Tests/Regions/LinvelBeechPreview.tscn` и нажать F6.
1–5 выбирают опушку, двор лесорубов, мост, солнечную поляну и дальний лагерь.
6 показывает лесную тропу, Tab — общий план, стрелки перемещают камеру.
Капсула здесь служит ориентиром масштаба; это осмотр окружения, а не сетевой клиент.
У общего плана временно отключены fog и отсечение дальних объектов.

## Где редактировать

| Файл или узел | Назначение |
| --- | --- |
| `Scenes/Regions/Linvel/BeechValley.tscn` | Основная сохранённая сцена, без runtime-генерации и скриптов |
| `Geometry/Ground` | Объёмный terrain mesh и его физическая поверхность |
| `Geometry/BridgeDeck`, `BridgeRail*`, `ShelterPost*` | Проходимый мост, ограждения и опоры |
| `Places` | Вручную редактируемые композиции и маркеры пяти мест |
| `Woodland`, `Undergrowth` | Сохранённые MultiMesh по ячейкам 40 м |
| `HeroTreesAndRocks`, `ClearingDetails` | Отдельные камни, деревья и растения |
| `Assets/World/Linvel/Beech/Meshes` | 22 общих нативных mesh-ресурса, включая terrain и stream |
| `Assets/World/Linvel/Beech/painted_forest.tres` | Общая текстура и мягкий стилизованный свет, прореживание перед игроком |
| `Content.Server/Data/regions.json`, `linvel_beech` | Серверные спавны, переходы, публичные ориентиры и настройки региона |

Пути без `Content.*` в таблице относятся к `Content.Client`. Деревья и низкая
растительность имеют ограничение дальности отрисовки. Не все фоновые стволы
имеют отдельный коллайдер: ближние препятствия и важные конструкции выделены явно.
Это ограничение текущей итерации для проверки движения и окружения.

Исходники находятся в `art-source/linvel/beech`: два Blender-файла, собственные
текстуры, каталог 20 моделей и код авторинга. GLB экспортированы с UV,
применённым масштабом и осью Y вверх; персонажи не моделировались в Blender.
Художественная приёмка качества остаётся отдельной проверкой.

## Godot и Blender MCP

Сцены и Godot-скрипты создавались через MCP Toolkit. Модели и terrain mesh
создавались внутри Blender через Blender MCP. Повторное создание ассетов:
в Blender MCP выполнить `runpy.run_path` для соответствующего файла
`art-source/linvel/beech/tools/build_beech_assets.py` или `build_beech_terrain.py`,
затем вызвать возвращённый `build_assets` или `build_terrain` соответственно.
Перед повторным экспортом сохранить ручные изменения исходника.

`Tools/Linvel/BeechValleyAuthoring.gd` — инструмент редактора. `build` работает
только в пустой сцене и отказывается пересоздавать существующий `Geometry`.
Он сохраняет обычные editable nodes и MultiMesh, затем убирается из публичной сцены.
`repair` явно переимпортирует общие meshes и материалы; `conform_to_ground`
переставляет объекты по высоте, сохраняя X/Z; `polish_clearings` выполняется
один раз и защищает повторные вызовы метаданными. Ни один из этих методов не
запускается автоматически в игре. Для ручного редактирования они не нужны.

После изменения коллизий, маркеров или сцены выполнить:

```powershell
./tools/Export-Regions.ps1 -GodotPath 'D:/Godot_v4.7.1-stable_mono_win64/Godot_v4.7.1-stable_mono_win64_console.exe'
```

Экспорт проверяет и публикует пакет только после валидации. Для леса используются
редактируемые metadata: cell size 0,5 м, cell height 0,05 м, detail distance 24,
detail error 4. Recast округляет радиус 0,45 м до 0,5 м. Пары треугольников
упаковываются без изменения диагонали и исходных высот; координаты — до 1 мм.
Итог: 3766 вершин, 2818 полигонов, 235 LOS-преград, меньше лимита 256 KiB.

Публичная геометрия леса имеет schema V2 с `WalkableFacesOcclude=true`: холмы
блокируют атаки. Schema V1 и hashes старых TerrainTest/DungeonTest сохраняются.
Транспортные message IDs, частота snapshots и persistent SQL schema не менялись.
Старый клиент без поддержки V2 не сможет активировать этот регион.

Изменение геометрии меняет её hash; автоматическая миграция сохранённых позиций
на другую поверхность не выполняется. Рабочую базу нельзя подменять тестовой:
перенос существующих персонажей потребует отдельного решения.

## Настоящий клиент и сервер

Для отдельного локального теста использовать свободный порт и отдельную БД:

```powershell
$env:DOTNET_ENVIRONMENT = 'Development'
dotnet run --project Content.Server -- --Server:Port=19071 --Server:StartingRegion=linvel_beech --Persistence:SqlitePath=D:/projects/project-g/.artifacts/linvel-beech-playtest/world.db
```

Во втором терминале запустить клиент с новым профилем:

```powershell
& 'D:/Godot_v4.7.1-stable_mono_win64/Godot_v4.7.1-stable_mono_win64_console.exe' --path Content.Client res://Scenes/World.tscn -- --server-port=19071 --identity=linvel-beech-playtest
```

Клиент использует обычное управление проекта. Для автоматической проверки
заменить `res://Scenes/World.tscn` на `res://Tests/Regions/LinvelBeechLiveSmoke.tscn`.
Она создаёт новый тестовый профиль, проверяет RMB через настоящий physical ray,
движение, совпадение высоты фигуры с сервером и возвращение к началу.

Стартовый регион обычного проекта не менялся. В прототипной карте есть служебный
переход в лес около X=-24, Z=18. Пока нет Линвеля и его таверны, возрождение
лесного теста находится на опушке. Её safe-зона — временная настройка прототипа,
не окончательное правило PvP для котловины. На солнечной поляне размещён один
существующий `test_creature`; лорные кагеры, их AI, задания и награды ещё не добавлены.

## Проверка этой итерации

`dotnet build Game.slnx --no-restore -m:1` прошёл без ошибок. Сохраняются ранее
существовавшие предупреждения NU1900/NU1903. 52 релевантных теста прошли без skips:
навигация, LOS, сетевое движение, старые регионы, появление и сохранение высоты.
Два UDP-клиента пересекли мост и получили одинаковые elevated snapshots.
Сцена осмотрена через MCP в Mobile renderer на RTX 4060 Laptop; настоящий
Godot-клиент прошёл `LINVEL_BEECH_LIVE_OK` на отдельной SQLite.

При запуске через MCP Toolkit редактор сообщает `Do not use progress dialog
while flushing the message queue` и отмену задачи progress dialog. Предпросмотр
при этом запускается; отдельно прочитанный журнал игры не содержит этих ошибок.
Диагностика интеграции Toolkit с редактором остаётся открытой.

Не проверена нагрузка 15 клиентов и не выполнена художественная приёмка.
Регион не содержит 20–30 часов готового контента: для этого нужны занятия,
лут, профессии, квесты, боссы и остальные области, предусмотренные паспортом альфы.

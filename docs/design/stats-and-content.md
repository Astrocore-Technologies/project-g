# Этап 4 — контент и характеристики

Статус: этап 4 принят пользователем. Основа влияний согласована; численный баланс временный. Использование характеристик в ручной тренировочной атаке описано в `docs/architecture/0005-manual-basic-attack.md`.

## Границы

Все определения и формулы находятся на сервере. Клиент, Shared, сетевой протокол v4 и сохранения не изменены. Нет атак, применения эффектов, ресурсов, предметных экземпляров, прогрессии или AI: это следующие этапы.

Сервер загружает `Content.Server/Data/prototype.json` один раз до открытия UDP-порта. Файл копируется при build/publish. `ContentCatalog` хранит immutable definitions в frozen dictionaries; данные не читаются в tick и не рассылаются клиентам. `StatCalculator` — отдельная чистая серверная логика, зарегистрированная в DI. На этом этапе её результаты ещё не добавлены сетевым игрокам.

## Данные

Текущая схема после этапа 6 — **schemaVersion 2**: способности получили уникальный ненулевой `networkId` (ushort), `speed` и `magicAttackScale`. Cooldown/cast/resource исполняются сервером; отрицательный производный MaxMana не меняется как стат, но текущий запас и его ресурсный максимум в этом прототипе ограничены снизу нулём. Регенерация пока не включена. Ниже сохранено описание этапа 4; изменения исполнения — `docs/architecture/0006-active-abilities.md`.

- `schemaVersion = 1`: версия структуры файла, независимая от протокола; неизвестная версия отклоняется, автоматических миграций пока нет.
- `balanceVersion`: положительная ревизия коэффициентов, повышается при изменении баланса.
- `balance`: коэффициенты влияний, базовый критический шанс и масштаб защиты.
- `weapons`: стабильный ID, Melee/Ranged/Magic, базовая атака, интервал в секундах, дальность.
- `abilities`: ID, Projectile/GroundArea/Dash, сила, mana cost, cooldown, cast time, range/radius. Это метаданные прототипа, не окончательная схема всех способностей.
- `creatures`: шесть характеристик, базовые HP/мана, восстановление в единицах за секунду, ссылка на оружие и список способностей. Опциональный `modifiers` — знаковые добавки к производным статам, по умолчанию ноль.

Основные поля обязательны, неизвестные свойства и повторные JSON-ключи запрещены. ID: до 64 символов `[a-z0-9_.-]`, уникальность в пределах вида определения. Все ссылки проверяются; дубли способностей и null запрещены. Размер файла ≤ 4 MiB, глубина ≤ 16, количество каждого вида определений ≤ 4096. Это бюджеты загрузчика, не игровые лимиты.

Невалидные числа, отрицательные базовые характеристики, ошибочные диапазоны, отсутствующие поля/ссылки обнаруживаются при загрузке. Ошибка содержит имя файла и причину; старт сервера прекращается до создания сетевой сессии.

## Правила

Все STR/AGI/VIT/INT/DEX/LUK конечны и неотрицательны. Производные статы могут быть отрицательными через модификаторы. MaxHealth остаётся положительным; текущее HP, смерть и восстановление ресурсов появятся вместе с соответствующими механиками.

Начальные коэффициенты вдохновлены предложенной пользователем Ragnarok-системой, реализация написана для Project G, код других игр не копируется:

| Стат | Начальные вклады |
|---|---|
| STR | Melee Status ATK +1; ranged +0.2; melee Weapon ATK multiplier +0.005 |
| AGI | attack speed contribution +0.01; physical defense +0.2 |
| VIT | HP contribution +0.01; HP item +0.02; DEF +0.5; MDEF +0.2; HP recovery +1/30 в секунду |
| INT | MATK +1.5; mana/mana item +0.01; MDEF +1; mana recovery +1/36 в секунду; cast speed +0.005 |
| DEX | ranged ATK +1; ranged weapon +0.005; melee/MATK/MDEF +0.2; attack speed +0.0025; cast speed +0.01 |
| LUK | melee/ranged/MATK +1/3; критический шанс через плавную кривую odds |

AGI не влияет на скорость перемещения. Нет Hit/Flee/Perfect Dodge, случайного отменённого попадания, веса, пороговых иммунитетов, сопротивлений статусам и влияния удачи на лут/заточку/секреты. Нет job/class bonuses, level scaling и покупки очков характеристик.

## Формулы прототипа

`x = сумма(stat × coefficient)`. Считается без округления промежуточных вкладов.

Положительная шкала:

```
P(x) = 1 + x       при x >= 0
P(x) = 1 / (1 - x) при x < 0
```

Она непрерывна, имеет одинаковый наклон около нуля, не содержит сингулярности при отрицательном x. Числовые guards ограничивают только переполнение double и underflow, не значения характеристик по игровому cap.

- Базовые MaxHealth/MaxMana: `base × P(x)`.
- Множители оружия, предметного лечения, скорости атак/каста: `P(x)`.
- Status ATK/MATK/DEF/MDEF: `x`.
- Восстановление: `base + x` для x ≥ 0; `base × P(x)` для x < 0.
- Затем прибавляются знаковые `modifiers`; только MaxHealth защищён от нулевого/отрицательного максимума техническим `double.Epsilon`. Это не текущий HP и не правило бессмертия/смерти.
- Сила оружия: `max(0, Status Attack + Weapon Attack × Weapon Multiplier)`; magic weapon пока имеет множитель 1.
- Интервал атаки/каст: `base duration / P(raw speed multiplier - 1)`. Без отрицательных модификаторов при статах ≥ 0 это обычное деление на полученный множитель. При штрафах скорость плавно снижается, но длительность не инвертируется. Базовый нулевой каст остаётся нулевым; положительный не становится мгновенным на пороге.
- Крит: начальные odds `p0 / (1 - p0)` умножаются на `P(LUK × coefficient)`, затем переводятся в вероятность `odds / (1 + odds)`. При p0 = 0.05 и coefficient ≈ 0.0631579 начальная производная ≈ +0.3 процентного пункта на LUK, но далее рост плавно замедляется. Это не точная линейная RO-формула. После модификатора сырой крит-стат может быть знаковым; `CriticalProbability` ограничивает именно вероятность действия диапазоном [0, 1]. RNG здесь не реализован.
- Защита: для D ≥ 0 `damage / (1 + D / K)`; для D < 0 `damage × (1 - D / K)`. K = 100 в данных; DEF 100 даёт половину урона, DEF −100 удваивает. Урон не превращается в лечение.

При численном переполнении операции насыщаются до конечного `±double.MaxValue`. Расчёты не возвращают NaN/Infinity для валидных входов. Точность при экстремальных значениях ограничена double; это не обещание игрового баланса на таких значениях.

Знаковые MaxMana, recovery и item modifiers поддерживаются как данные. Их применение к текущим ресурсам, drain/regen, зельям и бою пока не выполняется; правила исполнения будут частью соответствующего этапа.

## Приёмка

1. `dotnet run --project Content.Server -- --validate-content` — загрузить и проверить каталог без открытия порта.
2. Проверить `prototype.json`, коэффициенты и таблицу влияний.
3. `dotnet test Content.Tests/Content.Tests.csproj` — проверить доменную математику, крайние значения, модификаторы и загрузчик.
4. При изменении файла нужен повторный build/run; live reload пока отсутствует.

Godot-представление не изменялось. Этап 5 начинается только после пользовательской приёмки этапа 4.

Проверено при реализации: изолированный `dotnet build Game.slnx --artifacts-path .artifacts/stage4 -m:1` (0 ошибок, NU1900 из-за недоступности NuGet-аудита), 108 тестов через `dotnet test Content.Tests/Content.Tests.csproj --artifacts-path .artifacts/stage4 --no-build` вне песочницы, запуск собранного сервера с `--validate-content` (3 оружия, 3 способности, 2 существа). Обычный каталог сборки удерживался запущенным пользовательским сервером; его процесс не останавливался.

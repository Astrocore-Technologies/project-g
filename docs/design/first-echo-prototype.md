# Этап 10 — первое Эхо

Реализован полный первый игровой цикл Эхо; приёмка пользователем ещё не проведена.

Мира — защитница-компаньон. Один экземпляр выдаётся один раз при первом входе, включая старых персонажей.
Это временный тестовый контент, не постоянное правило получения Эхо. Баланс и имя находятся в серверной
конфигурации `Echoes`; клиент не получает внутренние definition IDs или persistent UUID.

## Поведение

- Следует за хозяином по навигации, обходит препятствия, не телепортируется.
- Помогает после ручной атаки/способности хозяина или полученного им удара.
  Не ищет врагов самостоятельно; помощь ограничена временем и расстоянием от хозяина.
- Базовая атака: физическая сила 8, дальность 2, интервал 1.2 с.
- Signature «Прикрытие»: ручная команда T в точку под курсором; физический AoE,
  дальность от Эхо 6, радиус 2, сила 24, cooldown 8 с. Стены блокируют применение и попадания.
- При смерти хозяина прекращает движение/атаки; после Development-оживления снова следует.
  Короткие реплики в UI отражают готовность, Signature, смерть и восстановление хозяина.
- Ядро поддерживает три активных слота (T/Y/U), но прототип выдаёт только Миру в первом слоте.

Временное prototype assumption: Эхо пока не получает урон. Постоянные правила смерти/возвращения Эхо
не согласованы. Это не добавляет immortality как постоянное gameplay-правило.
Affinity, резонанс, дубликаты, gacha и полноценные личные истории относятся к этапу 19.

## Authority, сеть и сохранение

AI, маршруты, урон, ownership, cooldown, sequence/flood/state/range/LOS проверяются сервером на fixed tick.
Клиент передаёт слот и намерение применения, не результат и не позицию Эхо. UI timer — только отображение.
Эхо не атакует игроков или других Эхо; постоянные PvP-правила здесь не вводятся.
Idle AI спит; AoE использует spatial index. Эхо включены в существующий AOI, runtime ID общий с другими сущностями.

Protocol v13: IDs 35..39 — spawn, signature command/result, action, owner-only loadout (ReliableOrdered).
Частые координаты передаются существующими Unreliable snapshots с interpolation на клиенте.
Боевое событие Эхо отправляется после более ранних событий tick, чтобы HP не откатывался к старому значению.

Additive schema v4 в Content.Database, Echo model v1 отдельно от character/inventory model v1.
Сохраняются stable instance UUID, definition, слот, координаты и остаток обоих cooldown.
Первоначальные null-координаты ставят старому персонажу Эхо рядом с его сохранённой позицией;
после первого commit сохраняются реальные координаты. Невалидные данные fail closed, без reset/повторной выдачи.
Offline время уменьшает cooldown по существующему правилу персонажа, маршруты не восстанавливаются.
Сохранение Эхо атомарно с character/inventory; публикация действий и координат — только после commit.
NPC/босс, как и ранее, не persistent.

## Ручная проверка

1. Штатно остановить сервер; сделать backup SQLite; перезапустить сервер и клиентов на v13.
2. Войти Alice/Bob разными профилями, проверить видимость обоих Эхо и обход препятствий.
3. Атаковать LMB манекен/врага: Мира помогает, без действий хозяина не начинает охоту.
4. Навести курсор на врага и нажать T: AoE, HP и cooldown одинаковы у двух клиентов.
5. Проверить стену/слишком дальнюю точку/повторное T, смерть и Development-оживление через I.
6. Reconnect/restart тем же профилем: один прежний экземпляр, позиция и cooldown сохранены.

SQLite/UDP тесты не заменяют визуальную приёмку; live PostgreSQL требует отдельного прогона.

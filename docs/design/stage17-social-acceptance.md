# Этап17 — домашняя приёмка

Нужны сервер и клиенты одной версии protocol23. Запуск с отдельными --identity=first / second / third. Рабочая БД автоматически получает additive schema8; не удалять старые данные.

1. N: создать party6, пригласить видимого второго игрока, принять на втором. Третий не видит чужого приглашения/состава. Два участника видят подтверждённый roster и HP/позиции. Выйти из AOI: нет дальнего avatar, HUD показывает свежую позицию участника.
2. Проверить передачу лидера, расширение20, сокращение6; при>6 сокращение отклоняется. Offline участник сохраняет слот; HP/позиция не выглядят актуальными. Лидер offline120с — earliest online leader; reconnect не забирает лидерство обратно.
3. В группе включить PvP вне города: melee/projectile/AoE/Echo не наносят друг другу урон; NPC и посторонние действуют по stage16. Tag/aggressor/cast/effects блокируют выход/исключение/смену состава. EXP не начисляется пассивно. Ручной лут не резервируется группой.
4. O: создать гильдию с Unicode именем, проверить case/space-дубликат. Пригласить/принять, назначить officer. Officer может исключить Member, но не другого Officer/Leader, и не повышает себя. Передача лидера — отдельное предложение и явное принятие получателем.
5. Guildleader не может выйти до передачи. Единственный последний лидер распускает гильдию через checkbox. Имя можно занять новой гильдией; старый ID не возвращается. Общая гильдия без общей party не защищает от PvP.
6. Reconnect/restart: party/guild/роли и public handles сохраняются, приглашения исчезают; party leader grace начинается заново. N/O панели не дублируются после reconnect. Проверить обычное и расширенное roster на малом окне.

Godot executable в Codespace не доступен: C# build/UDP checks не заменяют визуальную приёмку. Проверка не отмечается принятой до результата пользователя.

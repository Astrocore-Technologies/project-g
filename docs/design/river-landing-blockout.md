# Окраина Речной пристани — blockout и подключение к игре

Статус: blockout подключён к существующему игровому контуру; ожидает пользовательской приёмки.
Отдельные контроллер, тестовый персонаж и альтернативная навигация не используются.
Размеры, художественные решения и размещения предварительные. Это дополнительный
авторский preview по запросу пользователя, не завершение R2–R8 и не готовый регион сервера.

## Запуск

Открыть `Content.Client/Scenes/Regions/RiverLanding/RiverLandingBlockout.tscn`
в Godot .NET 4.7.1 и нажать F6. F5 запускает прежнюю main scene.

- Tab: общий план / перспективная камера осмотра.
- 1–6: двор, дорога, развилка, роща, мост, лесная тропа.
- Стрелки: сдвиг камеры осмотра без вращения.
- Капсулы — статические ориентиры масштаба. F6 пока проверяет только сцену.

В игре уже используются PlayerAvatar.tscn (персонаж + CameraRig), PlayerController
(input/prediction/reconciliation), NetworkClient и общий NavigationMover/Pathfinder.
Для новой локации нужно использовать именно их. Камера BlockoutPreview служит
только осмотру макета и не заменяет игровую камеру.

## Компоновка

Предварительные bounds: X от −40 до 40, Z от −32 до 32; верх плана — −Z.
Две основные петли: двор → развилка → роща → боковая тропа → двор;
развилка → роща → лесная тропа → площадка моста → развилка.
От двора также идёт короткая тропа к берегу. Дома и роща оставляют открытые площадки
для клика и обхода. Дороги показывают предпочтительное направление, не ограничивают
движение только своим полотном.

| Место | X / Z | Назначение |
| --- | --- | --- |
| Двор | −12 / 18 | Вход со стороны пристани, обзор домов и мастерской |
| Дорога | −8 / 7 | Проверка габаритов прохода между строениями |
| Развилка | −6 / 0 | Выбор между рощей и мостом |
| Роща | −24 / −10 | Ресурсная полянка, боковой путь |
| Площадка моста | 14 / −10 | Место сбора группы и будущего совместного события |
| Лесная тропа | −8 / −25 | Продолжение региона и обход через поляну |
| Резерв encounter | −23 / −22 | Будущее размещение противников, без принятия правил агрессии |

Река занимает X=20..28; мост пересекает её при Z=−10. Русло понижено визуально;
прохода под мостом нет. Два дома, открытая мастерская, 15 деревьев и несколько
каменных объёмов — временные массы для проверки пространств, не утверждённый asset list.
Здания/деревья вынесены в переиспользуемые PackedScene. Terrain, дороги и размещения
хранятся непосредственно в .tscn; preview script не строит уровень.

## Границы данных

Используется RegionRoot и authoring markers предыдущего R1. RegionId `prototype`
обозначает вариант проекта стартового региона, не новый опубликованный регион.
Этот файл не добавлен в manifest и не подменяет существующую серверную карту.
Preview/Labels/ScaleReferences предназначены для разработки и должны быть исключены
из будущей игровой сборки сцены. Маркеры содержат только placement/public footprint.

Physics layer 1 — walkable ground/deck, layer 2 — blockers. Проходимость всей реки
закрыта, кроме настила; его proxy не закрывает проход. Shapes упрощены и не являются
серверной navigation. Размер 80×64 при метровой клетке превышает demo limit 1024.
Экспорт в сервер требует согласованного backend; поднятие этого лимита здесь не сделано.
Настоящие склоны, закрытие моста, secret unlock и combat travel правила не добавлены.

## Подключение существующих систем — реализовано 2026-10-09

1. Экспортировать согласованную проходимость из authored collision в серверные данные.
2. Загружать окружение сцены через текущий WorldController, исключив повторное
   процедурное построение тех же стен/земли.
3. Создавать прежний PlayerAvatar по серверному spawn. Его PlayerController и камера
   остаются источником input/presentation; NavigationMover остаётся общим с сервером.
4. Проверить движение двух клиентов, совпадение коллизий/маршрутов, мост и reconnect.

Временный bounded backend расширен до 6144 клеток (эта карта занимает 5120).
Protocol25: RegionNavigation (ID14) передаёт bitset вместо байта на клетку,
RegionEnter (ID81) дополнен ulong geometry hash после Radius. Control/bootstrap
остаются ReliableOrdered; движение/snapshots не меняют delivery. Exploration reader
учитывает новый размер; максимальные карты с envelope остаются меньше 1200 bytes.
Это не production navigation больших регионов и не завершение R7/R8.

FlatGeometryBake экспортирует axis-aligned Box collision, полный опорный пол Y=0 и
repair patch из самой сцены. Сервер читает `Data/Regions/river-landing.json` без Godot.
Клиент сверяет hash до появления персонажа, удаляет inspector/scale references,
не строит старую землю/дома поверх сцены. PlayerController и камера не заменены.
Изменение сцены требует запуска `Tests/Regions/ExportRiverLanding.tscn` через Godot,
затем сборки и перезапуска сервера. Новые формы/высоты exporter отклоняет.

По решению пользователя все legacy-персонажи при следующем входе перемещаются
в пристань (-12,18); stable character/item/Echo IDs, stats, HP, progression, профессии,
валюта и прочее состояние сохраняются. Старые открытые клетки карты проецируются
по мировым координатам; архив outskirts остаётся. WorldLayoutVersion=1 предотвращает
повторный перенос после reconnect/travel. Миграция атомарна под character lease.
При старте SQLite host создаёт online backup `.before-river-landing-<id>.bak` рядом
с исходным db (включая committed WAL). Для отката остановить сервер и восстановить
совместимый комплект binary/content и backup БД; не запускать старый binary поверх
мигрировавших документов. Рабочая БД в тестах не изменялась — проверялась её копия.

По замечанию пользователя удалён добавленный во время разработки offline-дубликат
BlockoutWalkProbe/BlockoutNavigation и его тесты. Он не решал подключение к игре.

## Проверки

- `dotnet build Game.slnx --artifacts-path .artifacts/river-blockout -m:1`,
  финальный rebuild с `--no-restore`: успешно, 0 ошибок; NU1900 — недоступен NuGet audit.
- Обычная build попытка упёрлась в DLL запущенного сервера. Сервер не останавливался;
  отдельный artifacts output решил конфликт. В обычном output также был прежний NU1903 SQLite.
- Godot headless `res://Tests/Regions/RiverLandingBlockoutSmoke.tscn`: успешно.
- Тот же smoke с настоящим D3D12 Forward Mobile rendering и аргументом `--capture`:
  успешно; кадры overview/yard/grove/bridge сохранены в `.artifacts/river-landing-*.png`.
- Проверены authoring structure/IDs, шесть камер, точки осмотра, центральные линии
  дорожек относительно physics proxies, отсутствие пола над рекой, настил и lifecycle.
- Изображения изучены: поправлены общий обзор, ambient light, подписи в игровой камере
  и наложение ресурсной полянки на дорогу.

Проверки выше относятся к первоначальному offline blockout. Проверки интеграции:

- `dotnet build Game.slnx --no-restore -m:1`: успешно; существующие NU1900/NU1903
  (недоступный audit и SQLitePCLRaw 2.1.11) остаются отдельным dependency-риском.
- `dotnet test Content.Tests/Content.Tests.csproj --artifacts-path .artifacts/river-live --no-restore -m:1`:
  449 passed, 6 PostgreSQL skipped. С `PROJECT_G_MIGRATION_SOURCE` проверена online-копия
  текущей `.data/project-g-development.db`; исходная БД не менялась.
- Проверены улицы/роща, запрет прохода через дома/реку, ремонт моста и обновление
  кэша pathfinder, packet bounds/padding, SQLite migration+повторный вход, UDP два клиента
  100–150ms/10% loss, переход и crash/restart на новом executable/content.
- `Tests/Regions/RiverLandingLiveSmoke.tscn`: реальная World.tscn, PlayerAvatar,
  камера, RMB input и серверное подтверждение движения. Forward Mobile кадр проверен:
  `.artifacts/river-live.png`. Сервер smoke использовал отдельный порт и SQLite, остановлен.
- Server `--validate-content` и `git diff --check`: успешно.

Crowd capacity, Mobile performance и полная асинхронная load/readiness machine
не проверены этим шагом. Загружается маленькая сцена синхронно до spawn;
правило combat travel и второй legacy-регион не перепроектированы.

## Ручная приёмка

Запустить сервер в Development и нажать F5 в Godot. При первом входе старый персонаж
переносится на новую карту без сброса прогресса. ПКМ — движение; остальные действия прежние.
F6 на blockout — только инспектор. Проверить улицы, рощу, мост и повторный вход.
Не переходим к художественным ассетам до подтверждения пользователя.
Размер и визуальное направление остаются предварительными.

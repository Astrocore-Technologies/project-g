# Этап 12 — первая скрытая профессия

Статус: реализована, ожидает ручной проверки. Этап 11 пользователь проверит дома;
продолжение этапа 12 явно разрешено, визуальная приёмка этапа 11 не объявлена.

## Игровое поведение

Изначально персонаж без профессии. Игра открывает возможность стать «Хранителем троп»;
это предложение, а не автоматическая смена. Окно P до открытия не показывает имя,
список скрытых профессий, условия или прогресс выполнения. После открытия имя известно владельцу.

«Рассмотреть переход» получает краткоживущее подтверждение сервера. Затем отдельное предупреждение
называет текущую и будущую профессии, объясняет замену единственной активной профессии и запрет возврата.
Игрок отмечает понимание необратимости и нажимает отдельную кнопку подтверждения. Есть отмена.
Закрытие окна после получения подтверждения отменяет подготовку. Отмена сохраняет открытую возможность.

Успешная смена выдаёт фиксированный навык «Импульс» уровня 1 вне панели. Его можно назначить через K.
HP, mana, stats, предметы, EXP и прежние cooldown не сбрасываются. Нет переключения назад,
классового меню или клиентского запроса выдать профессию/записать историю. Retired IDs сохраняются.
Сохранение прежних изученных навыков — временное поведение этого среза; постоянная политика навыков
при смене между разными профессиями здесь не закрепляется. В игровых данных сейчас одна профессия;
смена одной уже активной профессии на другую проверена отдельной fixture с двумя определениями.

## Только для разработки: временные условия

Серверные данные prototype.json → professions: discoveryMask 3 (оба открытия этапа 11),
successfulUses 3 (три подтверждённых успешных применения навыков, включая завершённый живой рывок).
Порядок этих действий произволен. Начальная история успешных действий до внедрения этапа 12 неизвестна,
поэтому у старого документа она начинается с 0; сохранённые открытия, EXP и освоение остаются прежними.
Это тестовые условия, имя и навык, а не постоянные правила источников профессий или уникальных one-of-one профессий.
Lore/events/world-state и правила уникального владения не реализуются этим срезом. Этап 13 не начат.

Счётчик берёт события authoritative AbilitySimulation.Practice, а не packet arrivals.
Одна область по нескольким целям даёт одно действие. Пустая/отклонённая/replay/cooldown/flood-команда,
прерванный смертью рывок и ожидание не добавляют историю. Счётчик saturates на 10000.
Внутренние числовые thresholds, маски, история, catalog и unrevealed IDs не передаются клиенту.

## Протокол и сохранение

Protocol v15, reliable owner-only:

- 43 ProfessionCommand: uint sequence, byte action (Prepare/Confirm/Cancel), ushort professionId, uint confirmation. Payload 11 байт.
- 44 ProfessionState: ulong owner runtime ID, uint tick, ushort activeId + bounded name, ushort offeredId + bounded name. Только раскрытые identities; 0 ID означает пустое имя.
- 45 ProfessionResult: uint sequence, uint tick, byte outcome, uint confirmation. Payload 13 байт; ненулевой token только для Prepared.

Подтверждение случайное, session-bound, связано с offered/previous ID, одноразовое; срок 600 fixed ticks.
Заново проверить alive/busy, источник, ownership и отсутствие retired ID нужно при Confirm.
Новый запрос с invalid token, отмена, flood или удаление игрока уничтожает подготовку; reconnect не восстанавливает её.
Буфер входящих запросов ограничен двумя значениями на сессию, flood в одном tick отменяет mutation.
Никаких частых snapshots через reliable не добавлено; только команды, раскрытие и результаты.

SavedProfession v1 — optional versioned component внутри SavedProgression v1, в его существующей
opaque JSON записи schema 5. Отсутствующий компонент старого документа создаёт пустую историю;
присутствующий требует всех полей, корректной версии, bounded counters и уникальных retired IDs.
Content references/источники проверяются при входе; повреждение отклоняется без reset.
Это additive document extension, SQL migration не нужна. UUID/core/inventory/echo и существующие
модели остаются прежними. Старый strict binary новый компонент не читает: downgrade требует
контролируемой миграции; запускать client/server нужно вместе на protocol v15.

История, раскрытие, смена и новый навык сохраняются общей owner/revision-fenced транзакцией.
Состояние и результат Accept публикуются только после commit. При failure публикации нет.
Подготовка — временный session state без DB записи, профессию и навык не меняет.
Tick работает по событиям/очереди, не сканирует idle игроков; Godot types отсутствуют на сервере и в Shared.

## Ручная проверка дома

1. Запустить сервер и клиент protocol v15. P: нет скрытых имён/счётчиков/условий.
2. Посетить оба бирюзовых открытия и успешно применить навыки трижды. P сообщает открывшуюся возможность.
3. Рассмотреть переход и отменить; профессия и навыки прежние. Повторно рассмотреть.
4. Проверить предупреждение и необходимость галочки; подтвердить. Активна одна профессия «Хранитель троп».
5. K: «Импульс» уровня 1 вне панели; назначить слот и применить. Старые cooldown/HP/mana сохранены.
6. Переподключиться, затем перезапустить сервер: профессия, история, освоение и назначение сохранены.
7. Второй клиент не видит приватное предложение первого. До открытия его собственное окно пустое.

Автоматические проверки: ProfessionProtocolTests, ProfessionTests, ProfessionStorageTests,
ProfessionIntegrationTests. Integration использует 100–150 мс latency/10% loss, commit gate,
проверяет privacy, replay и reconnect. SQLite fixtures используют отдельные временные базы.

# GDD 01 — реализация боевой системы

Источник требований: [снимок GDD 01](gdd-01.md). Авторизация: пользователь 2026-10-15 потребовал заменить старую боевую систему и считать работу завершённой только после выполнения всего документа. GDD 02 не входит в объём.

## Решения пользователя

- D001: каждое открытое gameplay-правило согласовать до подключения; временные математические/ACR правила не вводить вместо ответа.
- D002: старых персонажей разрешено вайпнуть при переходе. Это не разрешение удалять несвязанные файлы/состояние мира. Рабочая БД пока не менялась.
- D003: `P(hit) = 1 / (1 + exp((Evasion − Accuracy) / 100) / 19)`, после геометрии, без Perfect Evasion и искусственного минимума.
- D004: `Accuracy = DEX + модификаторы`, `Evasion = AGI + модификаторы`, коэффициенты 1:1, скрытых базовых прибавок нет.
- D005: первый баланс модели B: все семь статов по 10, 18 свободных очков при создании, 5 за уровень.
- D006: `MagicATK = WeaponMagic + 3×INT + 0.4×LUCK`; `MaxMP = 60 + 8×WIS + Bonuses`; `MagicDefense = EquipmentMagicDefense + 1.5×WIS + Bonuses`.
- D007: `MPRegen = BaseMPRegen + 0.2×WIS + Bonuses`, единица MP/секунду.
- D008: по поправке пользователя `CriticalDamage = 1.5 + 0.01×DEX + модификаторы` (при 10 DEX ×1.6, при 100 DEX ×2.5). Critical Chance независим.
- D009: In Combat 30 с продлевается подтверждённым враждебным контактом (в том числе Block/Parry/Dodge/Evasion/контроль), периодическим уроном, лечением/щитом участнику боя. Пустой взмах/отклонённая команда бой не запускают.
- D010: `BlockStrength = 10 + STR + VIT + бонусы`; `BlockPressure = PowerBeforeCritAndDefense × PressureScale` (по умолчанию ×1); `HitStaminaCost = 10 × Pressure / Strength`. Поглощение независимо.
- D011: удержание блока 5 Stamina/с. При недостатке Stamina для входящего удара остаток снимается, удар не поглощается блоком, блок запрещён 1 с без стана.
- D012: сектор Block/Parry 120° (±60°); Parry 10 Stamina, окно 0.25 с, cooldown 0.5 с; допустимость защиты задаёт действие.
- D013: первый баланс ACR: λ=1, полный сброс через 12 с после последнего эффекта категории; бюджеты Hard 6 / Movement 5 / Action 6 / Soft 3 / Targeting 2 секунд.
- D014: успешное наложение расходует итоговую длительность, пересечения разных источников суммируются; refresh того же эффекта тем же источником расходует лишь добавленное время. Досрочное снятие не возвращает бюджет.
- D015: Knockback/Pull используют бюджет Movement через `duration = distance/speed`; ACR сокращает длительность и дистанцию при сохранении скорости.
- D016: Cast не резервирует MP/Stamina. При нехватке полной стоимости к моменту активации: срыв без основного эффекта, cooldown запускается, списывается до 50% полной стоимости из остатка без отрицательного ресурса.
- D017: заряды восстанавливаются последовательно по одному за cooldown. Использование оставшегося заряда не перезапускает текущий таймер.
- D018: по поправке пользователя обычный cooldown reset восстанавливает **все** заряды навыка.
- D019: смерть во время незавершённого Cast — до 50% полной стоимости из остатка, cooldown запускается, основной эффект не создаётся.
- D020: Charged использует схему Cast: добровольная отмена 0% без cooldown, вражеское прерывание 50% + cooldown, выпуск 100% + cooldown; сила задаётся данными навыка.
- D021: ACR для Slow сохраняет длительность и уменьшает силу; стоимость — итоговая сила × длительность с ограничением остатком бюджета. Slow складываются, минимум обычной скорости 10%.
- D022: Blind нормализуется через 100 Accuracy = сила 1; стоимость Soft-бюджета — итоговый штраф / 100 × длительность; ACR уменьшает штраф, длительность сохраняется. Accuracy допускает отрицательные значения.
- D023: стартовый Taunt penalty 30%; ACR уменьшает штраф при сохранении длительности, стоимость — итоговый штраф × длительность. Последний успешно наложенный Taunt имеет приоритет, затем возвращается предыдущий действующий. NPC принудительно выбирает провокатора без постоянного увеличения Threat.
- D024: иммунитет → сопротивление виду → сопротивление категории → ACR. Сопротивления 0–100%, оставшиеся множители перемножаются; сокращают время обычного контроля и силу Slow/Blind/PvP Taunt. Отклонённый контроль не меняет бюджет/сброс.
- D025: Knockup вместе с последующим Knockdown расходует Hard ACR по сумме длительностей; сокращение пропорционально обеим фазам, высота сохраняется.
- D026: refresh Slow/Blind/Taunt тем же источником и эффектом сохраняет действующую силу, продлевает время с учётом ACR и оплачивает лишь добавленное время × силу. После окончания сила нового наложения вычисляется заново.
- D027: PvE Taunt расходует Targeting ACR по длительности с весом 1 секунда внимания = 1 единица; ACR сокращает время принудительного внимания (первое максимум 2 с при текущем бюджете).
- D028: Fear запрещает ручное перемещение, обычные атаки, активные навыки, Block/Parry/Dodge; сервер ведёт цель от источника по навигации, камера и UI свободны.
- D029: стартовое окно Input Buffer — 150 мс.
- D030: CDR-модификаторы складываются, исполнение ограничивает итог 0–100%; cooldown = base × (1 − CDR). Текущий интервал фиксируется при его запуске, дальнейшее изменение CDR не пересчитывает идущий таймер. Обычный reset восстанавливает все заряды.
- D031: успешная активация, вражеское прерывание, смерть до активации и срыв из-за нехватки ресурса расходуют по одному заряду и запускают его восстановление. Добровольная отмена до активации не тратит заряд.
- D032: DoT/HoT по умолчанию фиксируют силу и параметры крита при наложении. Refresh обновляет снимок и срок, сохраняя следующий тик. Динамический расчёт допускается явным параметром конкретного эффекта.
- D033: офлайн срок эффектов истекает, пропущенные периодические тики не выполняются и не накапливаются. Оставшееся в мире тело до удаления симулируется обычно.
- D034: щиты поглощают после защиты/Block перед потерей HP; сначала ближайший срок окончания, затем порядок наложения; остаток проходит дальше.
- D035: Life Steal лечит от фактически снятого HP без нового крита; Mana Steal отнимает у цели MP по фактическому урону HP × коэффициент и возвращает реально отнятое. Direct/DoT eligibility задаётся эффектом; reflected damage и HP price не запускают steal.
- D036: отражение берёт долю фактически потерянного HP; возвращаемый урон проходит defense/shields без повторной Evasion/crit/Block/Parry. Отражённый урон не запускает отражение/steal, eligibility исходного урона задаётся данными.
- D037: первый периодический тик через полный интервал; тик ровно на expiry выполняется перед снятием. Число тиков не зависит от шага сервера. Offline пропускает прошедшие тики, сохраняя исходный ритм.
- D038: обычный shield refresh тем же источником заменяет оставшееся поглощение новым расчётом и обновляет срок; явная политика особого эффекта может суммировать.
- D039: HP price обходит защиту/щиты и не запускает combat procs; по умолчанию после оплаты HP > 0. Разрешение смерти от цены задаётся явно. Self-damage — отдельная операция.
- D040: DoT/HoT/shields живут независимо от смерти/выхода источника до expiry; удаление при смерти источника задаётся явным флагом. PvP permission DoT фиксируется на успешном наложении; текущая защита цели проверяется при получении урона.
- D041: HP damage → Life/Mana Steal → reflection. Eligibility/procs берутся в момент попадания, смертельный удар тоже отражается. Steal возвращает ресурсы только живому источнику и не воскрешает.
- D042: Bleed мечника — 0.6 базового обычного удара за 4 секунды, четыре Physical DoT тика через 1 с; крит только с разрешающей пассивкой, snapshot/refresh по общим правилам.
- D043: пользователь выбрал завершать незавершённое принудительное перемещение после аварийного перезапуска сервера. Это не обычный disconnect: при нём тело 60 с остаётся в мире и симулируется (GDD §11). Уже наступившее лежание остаётся обычным действующим контролем.
- D044: respawn доступен через 60 секунд после смерти, в заданной сервером точке возрождения региона; воскрешение на месте — отдельная операция.
- D045: по поправке пользователя respawn возвращает **50% HP и 50% MP**; Stamina до максимума из предложенного правила. Cooldowns, ACR, прочность и эффекты с persist-through-death сохраняются.
- D046: воскрешение на месте доступно в течение 60 секунд жизни тела; HP явно задаёт навык, MP/Stamina и cooldowns сохраняются, автоматической неуязвимости нет. После исчезновения тела остаётся respawn. Общая жизнь и authored операция GroundArea подключены; другие формы поддержки ещё требуют интеграции.
- D047: базовые разрешённые цели лечения, щитов и воскрешения — сам источник и его группа. Поддержка остальных игроков должна быть явно разрешена данными навыка. Проверка выполняется сервером при применении; уже наложенные HoT/щиты живут по согласованной независимой жизни эффекта.
- D048: журнал боя и разбор смерти доступны только владельцу персонажа; публичного доступа и передачи другим игрокам нет.
- D049: текущий сеанс хранит последние 200 боевых событий. Разбор смерти включает последние 30 секунд перед смертью, до 300 событий; сохраняются 10 последних разборов персонажа с восстановлением при входе.
- D050: обычное Parry доступно без оружия. Для Block голыми руками по §10.1 GDD требуется явное разрешение профессии/способности. Профиль и износ утверждены отдельно в D051/D052.
- D051: первый безоружный профиль: WeaponATK = 0; физический урон от MeleeATK; дальность 1 м; базовый интервал 1 с с обычным влиянием Attack Speed. Сломанное оружие трактуется как отсутствие оружия по §10.2.
- D052: WearPerHit списывается один раз за применение обычной атаки или оружейного навыка, только если оно фактически сняло HP. DoT и отражение не изнашивают оружие; Block/Parry/Evasion без потери HP не являются основанием износа.
- D053: Channeling расходует дробный ресурс без округления до целых. При исчерпании посреди fixed step выполняется только оплаченное время; неоплаченные тики не создаются, дополнительного штрафа 50% нет.
- D054: снаряды обычных атак и навыков фиксируют при выпуске силу урона, Accuracy и параметры крита источника. Evasion, защита, Block и щиты цели проверяются при контакте.
- D055: выпущенный снаряд продолжает полёт после смерти или выхода источника; отмена действия его не отзывает.
- D056: разрешение PvP для снаряда проверяется при контакте. После удаления источника используются сохранённые при выпуске принадлежность, режим PvP и позиция; защитное состояние цели проверяется актуальное.
- D057: попадание после смерти/удаления источника выполняет заданные DoT и контроль от сохранённого источника. Нужные характеристики отсутствующего/умершего источника берутся при выпуске; лечение/возврат MP умершему источнику не выполняются.
- D058: после аварийного перезапуска Channeling завершается без новых эффектов и расходов. Для cooldown, отложенного до завершения, по выбору пользователя запуск выполняется при входе без учёта офлайн-времени.
- D059: нажатие клавиши Charged начинает серверную зарядку; удержание позволяет наводить при разрешённом повороте; отпускание выпускает навык. Esc/ПКМ до выпуска — добровольная отмена по схеме Cast.
- D060: автоматический выпуск при полной зарядке либо удержание до отпускания задаются явно в данных каждого Charged-навыка, без общего скрытого выбора.
- D061: Hold начинается нажатием, продолжается удержанием и завершается отпусканием. Оплата фактически выполненной работы и момент cooldown задаются данными по принятой модели Channeling; добровольное завершение после активации не добавляет штраф 50%.
- D062: Toggle включается нажатием и выключается повторным нажатием. В данных явно задаются занятость обычного действия и события прекращения; одновременно исполняется только одно обычное действие.
- D063: смерть или полное удаление источника выключают Toggle. Уже наложенные эффекты живут по прежним правилам. После crash Toggle выключен; deferred cooldown начинается при входе без offline credit, как у Channeling.
- D064: Toggle оплачивается как Channeling: начальная стоимость при включении и фактически обеспеченное время, cooldown Activation/Completion явно в данных. Дополнительных 50% нет, включая прерывание подготовки; прерывание до активации расходует заряд/cooldown по D031.
- D065: снятие включённого Toggle с боевой панели выключает его до изменения панели и запускает предусмотренный cooldown.
- D066: изученный Passive работает без активного слота и не занимает обычное действие. Условия задаются серверными данными; при их изменении действие пассива пересчитывается. Ручной запуск Passive запрещён.
- D067: аварийный перезапуск во время подготовки Cast/Charged бесплатно завершает подготовку: без основного эффекта, списания ресурса, расхода заряда и запуска cooldown. Уже активированное поддержание восстанавливается по прежним D058/D063.
- D068: у фонового оружейного Toggle завершённый импульс является границей отложенной поломки. После применения износа требующий оружие Toggle выключается при поломке с предусмотренным cooldown; износ D052 остаётся один раз за включение.
- Старые боевые правила в gameplay-contract/ADR являются историей там, где противоречат GDD 01.

## Проверяемое основание B2 / B3 / B5

- Server owns interval and repeated swings. Client sends Manual / BeginContinuous / UpdateContinuous / EndContinuous, never damage or target lock.
- One input sequence can produce several server executions; execution IDs are independent of command acknowledgement.
- Release is terminal even when buffered behind a save; updates never restart an interrupted hold.
- Missing heartbeats expire a technical input lease. Death, accepted defense/skills and session teardown stop the hold.
- Семь статов, утверждённые формулы и owner-only preview/commit проходят через server → wire → UI. Balance Studio использует те же коэффициенты; отдельный устаревший CriticalMultiplier удалён.
- Character v2 требует WIS. Разрешённый reset v1 выполняется при входе одним checkpoint под прежней credential/lease, включая inventory/Echo/progression и ownership; рабочая БД не запускалась.

## Общая жизнь, тела и поддержка

- `CombatSimulation.Life`: смерть фиксируется однажды с ordinal DeathId, останавливает ввод/контроль и уведомляет потребителей; corpse/respawn deadlines обрабатывает sorted schedule. `SavedCombatLife` v1 включён в character v2 атомарно с HP, ресурсами и отдельными effect rows. - `ServerWorld.Life` принимает bounded RespawnCommand, проверяет ownership/loading/sequence/death ordinal/срок на fixed tick. Respawn использует серверную точку региона, D044/D045; stale/replay не возвращают ресурсы повторно. PK остаётся потребителем смерти: реальная смерть учитывается и при resurrection в том же тике.
